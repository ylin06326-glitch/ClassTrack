# ClassTrack YRL — 离线激活登录系统说明文档

> **版本**: v1.5  
> **性质**: 纯本地离线激活，全程无网络请求  
> **加密方案**: RSA-2048 非对称加密 + SHA-256 哈希校验

---

## 一、系统概述

ClassTrack YRL 在 v1.5 版本新增**启动激活登录校验模块**，采用 RSA 非对称加密 + 硬件绑定方案，实现软件授权管理：

- **软件端**: 内置 RSA 公钥，仅能校验激活文件，无法自行生成
- **商家端**: 持有 RSA 私钥，使用独立工具为用户生成绑定设备的激活文件
- **硬件绑定**: 激活文件绑定单台电脑，复制到其他设备自动失效

---

## 二、硬件码生成规则

### 2.1 采集优先级

| 优先级 | 采集内容 | 获取方式 |
|--------|---------|---------|
| 1 | CPU 序列号 + 磁盘序列号 | `wmic cpu get processorid` + `wmic diskdrive get serialnumber` |
| 2 | CPU 序列号 + 主板序列号 | `wmic baseboard get serialnumber`（磁盘不可用时） |
| 3 | MAC 地址 | `uuid.getnode()`（兜底方案） |

### 2.2 机器码生成算法

```
原始硬件ID = CPU序列号 + "|" + 磁盘序列号
机器码 = SHA256(原始硬件ID) → 取前128位(32 hex chars) → 8组4字符大写
展示格式: XXXX-XXXX-XXXX-XXXX-XXXX-XXXX-XXXX-XXXX
```

**示例**:
```
CPU序列号: BFEBFBFF000906A3
磁盘序列号: 1234567890
原始硬件ID: BFEBFBFF000906A3|1234567890
机器码: 8347-191C-D9AE-37C3-3BCA-D302-028C-A817
```

### 2.3 注意事项

- CPU 序列号返回 "TO BE FILLED BY O.E.M." 等无效值时自动降级
- 虚拟机环境下可能缺少硬件序列号，自动使用 MAC 地址
- 更换 CPU 或系统盘后需重新激活

## 三、加密校验流程

### 3.1 密钥体系

```
┌─────────────────────────────────────────────────────┐
│                    RSA 2048 密钥对                    │
├─────────────────────┬───────────────────────────────┤
│   私钥 (private.pem) │   公钥 (内置于 key_pair.py)    │
│   仅商家工具持有     │   编译进 ClassTrack.exe       │
│   用于签名激活文件   │   用于验签激活文件             │
└─────────────────────┴───────────────────────────────┘
```

### 3.2 激活文件格式

激活文件（`.dat`）内部结构：

```
===== CLASSTRACK ACTIVATION FILE =====
<Base64(JSON_Payload)>.<Base64(RSA_Signature)>
===== DO NOT MODIFY =====
```

**JSON Payload 字段**:

| 字段 | 说明 |
|------|------|
| `product` | 固定值 `"ClassTrack_YRL"`，防止跨产品激活 |
| `hw_hash` | 原始硬件ID的 SHA256 哈希（不存储原始硬件ID） |
| `machine_code` | 展示用机器码前32位 |
| `issued_at` | 生成时间 |
| `version` | 格式版本号 `"1.0"` |

### 3.3 启动校验流程

```
软件启动
    │
    ├── 采集本机硬件指纹
    │
    ├── 读取 data/activation.dat
    │   │
    │   ├── 文件不存在 → 弹出全屏激活页，锁定全部功能
    │   │
    │   └── 文件存在 →
    │       │
    │       ├── 解码 Base64(JSON) + Base64(Signature)
    │       │
    │       ├── RSA 公钥验签
    │       │   ├── 验签失败 → "文件被篡改"，锁定
    │       │   └── 验签通过 →
    │       │       │
    │       │       ├── 硬件码 hash 匹配
    │       │       │   ├── 不匹配 → "绑定其他设备"，锁定
    │       │       │   └── 匹配 → ✅ 激活通过，进入主界面
```

## 四、界面交互逻辑

### 4.1 全屏激活登录页

软件启动后**第一帧**弹出全屏液态玻璃激活页面，包含：

1. **Logo 区域**: 🎒 图标 + "ClassTrack YRL" 标题
2. **状态提示区**: 
   - `🔒 请粘贴商家提供的激活密钥`（默认）
   - `⏳ 正在校验激活密钥...`（校验中）
   - `✅ 激活成功！正在进入系统...`（成功）
   - `❌ 硬件码不匹配（激活文件绑定其他设备）`（失败）
3. **机器码展示框**: 8段4字符机器码 + 一键复制按钮
4. **密钥粘贴框**: 文本框，粘贴商家提供的激活密钥
5. **操作按钮**:
   - `✅ 验证激活` — 校验粘贴的密钥（支持 Ctrl+Enter 快捷键）
   - `复制机器指纹` — 复制完整指纹信息发送给商家
6. **备选方式**: 底部「📂 或选择激活文件导入」+ 拖拽 .dat 文件到窗口
7. **底部提示**: "未激活前，软件全部功能禁用"

| 场景 | 行为 |

## 七、商家工具使用说明

### 7.1 启动工具

```bash
python activation/merchant_tool.py
```

### 7.2 操作流程

1. 确认工具顶部显示 `🔒 私钥已加载`（绿色）
2. 让用户在激活页点击「复制机器指纹」
3. 粘贴到工具的输入框中
4. 点击「🔐 生成激活文件」
5. 在输出框确认内容生成成功
6. 点击「💾 保存为激活文件 (.dat)」
7. 将保存的 `.dat` 文件发送给用户

### 7.3 安全提醒

- ⚠️ **私钥文件 `private_key.pem` 绝密**，严禁随软件分发
- ⚠️ 商家工具应独立保管，不可与用户软件打包在一起
- ⚠️ 每个激活文件绑定单台设备，不可复用

## 八、安全设计

| 安全特性 | 实现方式 |
|---------|---------|
| 防篡改 | RSA 签名校验，任何修改导致验签失败 |
| 防复制 | 硬件码绑定，复制到其他电脑自动失效 |
| 防伪造 | 私钥仅商家持有，用户软件只有公钥 |
| 离线运行 | 全程无网络请求，无后台上传 |
| 防降级 | `before_request` 中间件拦截所有非白名单请求 |

## 九、常见问题

**Q: 更换电脑硬件后需要重新激活吗？**  
A: 更换 CPU 或系统盘后硬件码改变，需重新联系商家获取新激活文件。

**Q: 激活文件可以用于多台电脑吗？**  
A: 不可以。每个激活文件绑定单台设备，不同电脑的硬件码不同。

**Q: 卸载重装后需要重新激活吗？**  
A: 不需要。只要 `data/activation.dat` 文件保留即可。重装如果清除了 data 目录，需重新导入激活文件。

**Q: 商家工具如何保证安全？**  
A: 私钥存储在独立的 `private_key.pem` 文件中，与用户软件完全分离。商家应妥善保管此文件。
